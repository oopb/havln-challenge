# Eval-39 回退记录与后续修复设计（仅设计，尚未实施）

## 当前状态（回退后的基线）

以 eval-38 对应的 v23 实现作为传感器、安全和运动执行基线，只保留用户明确指定的 NavigationAgent **相对**转向：`turn_direction=LEFT|RIGHT|NONE`、非负 `turn_degrees`，俯仰由 `look` 控制；内部 yaw 来源标签仍允许存在。回退删除 v24 的 `near_field_proximity` 模型输入、`visible_people_boxes`、扩展人体缓冲硬拒绝、因人物框过期导致的动作中断、两项人体安全配置与新增相关测试。恢复 v23 原子前进 Depth 语义：只有经原先中心线复核确认的阻挡拒绝前进；UNKNOWN 并不等于 CLEAR，但不能仅因 UNKNOWN 强制转向。

**注意：**回退只是恢复可用性，不代表已经解决 eval-38 距离人物过近的问题；下一阶段必须独立验证人际间距、碰撞、导航步数。

## 现有证据与诊断目标

- eval-38：100 步内前进 22 次，进入 foyer；此前观察到接近人物的问题。
- eval-39：100 步内前进 4 次，转向 71 次，LOOK 24 次；47/47 次导航输入均附带近场占用；未出现 `human_buffer_confirmed=true`，并未由新的人体硬锁直接拒绝前进。
- `obs_0070` 类样本：`nearest_forward_m=0.05`, `nearest_lateral_m=-0.454`，表明宽区域中有侧方近点，而不代表机器人前方仅剩 5 cm 通行距离。
- eval-39 中 NavigationAgent 仍尝试将历史绝对 yaw 解释为当前 LEFT/RIGHT，造成转向方向与文字目标矛盾；应在未来修改历史方向 **展示**，而非重新允许输出绝对 yaw。
- 第一视角像素与 Depth 哈希来自诊断包；不要把图片中心的单个深度点、人的宽框中心或估计的平移当成真实碰撞裕量。

## 下一版候选修复：相互独立的四个阶段

### 阶段 A — Depth 近场信息纠偏（优先）

1. **不恢复**原始宽区域 `near_field_proximity`：不发送 `nearest_forward_m` + `nearest_lateral_m` 这一容易混淆的“最近点”组合。
2. 如果确实需要为模型展示近场证据，基于与前进方向一致的**下一原子步机器人圆柱扫掠/足迹**计算 `central_or_swept_path_obstacle` 和 `side_only_occupancy` 两个独立、有明确来源的字段；不将侧方墙、栏杆或边界当成正前方必须停步的信号。
3. 若只有少量可疑测量或传感器盲区，标 `UNKNOWN` 且不自动禁止；已确认的中心障碍沿用现有拒绝机制。
4. 在 eval-38/39 的原始 RGB-D 离线重放，逐帧比对“前进足迹内最近碰撞点”和“侧方最近点”，并记录导致误报的墙/栏杆/楼梯视角。新字段不是强制用户部署的前提。

**验收：**相同起点下，不能每次决策都因为侧方近点收到类似阻挡告警；楼梯前进时的硬安全拒绝不增加无证据的假阳性。

### 阶段 B — 相对方向的展示，不更改动作协议

1. 保持输出只有 `LEFT/RIGHT/NONE`、`turn_degrees`、`look`。
2. 对 **同一站位**、源 yaw 有效的历史视觉候选，使用确定性代码在输入投影中给出 `relative_side_from_current=LEFT|RIGHT|AHEAD`、`relative_offset_deg`、`source_observation_id`、`same_stance`，不让模型自己从 135°、210° 做空间减法。
3. 旧站位候选只能当“历史路线提示”，标明 `not_current_movement_direction`；不跨未验证平移外推路标。
4. 仅显示与当前任务最相关的最多 2–3 个候选，避免同一个航向冗余描述。

**验收：**固定历史候选单元测试检验源 yaw 和当前 yaw 的 LEFT/RIGHT，且 API 输出只出现相对动作字段；拒绝任何 `target_heading_deg` 工具参数。

### 阶段 C — 人体安全：语义检出与几何测量分离

1. 复用 ObservationAgent 已有的人物 box/语义与来源观测 ID，或使用轻量实时检测；若两者都不可用，不要声称已检测到人。
2. 人体框必须与当前 RGB 哈希、相机姿态、时间戳一致才可与当前 Depth 合并；不能简单套用历史人物框，也不能根据静态全图最近点认定人体距离。
3. 对有效人体区域计算深度分位数、身体占用的横向范围、与下一步**实际扫掠半径**的最近接触裕量；对缺失 Depth 显示不确定，而非假设有人或假设可通行。
4. 将人际间距提示（社会距离/舒适距离）与确认的碰撞风险分开；默认先向 NavigationAgent 输出附来源的结构化风险，只有可靠的即时几何穿越证据才可中断前进。
5. 只在接近人体、有新动态证据时触发额外观察；在远离人的楼梯段，不改变原有的连续前进机制。

**验收：**在 eval-38 的接近人物帧上报告更早的有效距离提示，不在 eval-39 的纯侧墙/栏杆帧上误判“人挡路”；不显著减少楼梯前进。

### 阶段 D — 决策收敛与 A/B

1. 不设置“转 N 次必须前进”“每次 MOVE 只能前进一次”等硬规则。给模型的是已回答的观察问题、当前候选路径与真实阻挡，不是强制行为。
2. 使用相同任务、同一起点、同一模型/seed、同一 100 步预算，至少对比 v23 基线、v25 回退版和候选版本；分别记录动作统计、有效前进段、原子 Depth BLOCKED、观察重复、合法方向、碰撞与官方 score。
3. 关键画面逐帧检查楼梯下行、foyer 人群间隙、是否发生近人擦碰；不能凭某次随机轨迹直接证明因果。
4. 分别提交 A/B/C 阶段的回归测试和小 PR；只有确认真实运行不回退时才叠加。保留独立回退点和源文件指纹。

## 首批离线测试矩阵

- `obs_0070`：侧偏 0.454m 的近点不得描述为 5cm 正面自由距离。
- `obs_0023/0053/0072`：原确认的中心障碍依旧 `BLOCKED`。
- eval-38 人物靠近帧：只有**有效来源的**人体像素及真实 Depth 可确认靠人风险。
- 楼梯/栏杆与人物同时入镜：宽通路不被人的大 box 中心替代；路口宽度必须看路径边界。
- 多步前进：远离人时连续动作数不受新增限制；有确证近人风险时返回新当前画面。
- 相对方向：LEFT/RIGHT 按当前机器人机体坐标执行；任何历史绝对 yaw 都不能变成模型输出动作参数。
